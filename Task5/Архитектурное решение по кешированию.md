## «Мотивация».
### Мотивация к внедрению кеширования

#### Почему необходимо кеширование

Кеширование — эффективный механизм повышения производительности информационной системы. Его внедрение обосновано следующими ключевыми факторами:

1. **Рост нагрузки на систему.** С увеличением числа пользователей и объёма данных серверные ресурсы испытывают возрастающую нагрузку. Кеширование снижает количество прямых обращений к основным источникам данных (БД, внешним API, файловой системе).

2. **Задержки при получении данных.** Доступ к «холодным» данным (из базы, удалённого сервиса) требует времени на:
* установление соединения;
* выполнение запросов;
* передачу данных по сети;
* обработку на стороне сервера.

Кеш устраняет эти задержки, храня «горячие» данные в быстродоступной памяти.

3. **Оптимизация использования ресурсов.** Сокращение числа запросов к БД и внешним сервисам:
* снижает нагрузку на CPU и дисковую подсистему;
* уменьшает сетевой трафик;
* продлевает срок службы оборудования за счёт снижения интенсивности использования.

4. **Улучшение пользовательского опыта.** Быстрая загрузка страниц и мгновенный отклик интерфейса напрямую влияют на удовлетворённость пользователей и конверсию.

5. **Масштабируемость.** Кеширование позволяет системе выдерживать пиковые нагрузки без немедленного наращивания аппаратных ресурсов.

#### Проблемы, решаемые кешированием

* **Высокие времена отклика** — медленная загрузка данных из-за удалённости источников или сложности запросов.
* **Перегрузка базы данных** — массовые однотипные запросы к БД, вызывающие «просадки» производительности.
* **Зависимость от внешних сервисов** — задержки и ошибки при обращении к API третьих сторон.
* **Избыточные вычисления** — повторный расчёт одних и тех же данных (агрегации, трансформации).
* **Неэффективное использование пропускной способности сети** — многократная передача идентичных данных.


## «Предлагаемое решение»
- MES API -> MES db - Refresh-Ahead + Write-Through. RA работает для обеспечеыния отображения свежих заказов, который можно вязть в работу. WT - обновляет кеш, помечая заказы как взятые в работу.
- Internet Shop -> Shop API - Cache-Aside. Храним стат данные на стороне клиента. 
- Shop API -> Shop DB - Read-Through. Храним данные о прочитаном заказае по TTL, чтобы предотвартить повторыне чтения из постоянного хранилища
- CRM -> CRM API - Cache-Aside. Статические данные о заказе. Уменьшаем кол-во данных передаваемых по сети
- CRM API -> 3d files storage - Read-Through. Храним данные о прочитаном заказае по TTL, чтобы предотвартить повторыне чтения из постоянного хранилища
