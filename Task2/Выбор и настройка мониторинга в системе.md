## «Мотивация»
О проблемах сообщают пользователи или представители бизнеса. И у  «Александрит» нет возможности узнать о проблемах раньше. Чтобы эффективно решить проблему, нужно быть в числе тех, кто первым её заметил. Поэтому лучше всего самостоятельно следить за состоянием приложения.
В работе с современными распределёнными системами немало сложностей и подводных камней. Их можно обнаружить на каждом этапе жизненного цикла — во время разработки, тестирования, развёртывания и запуска в производство

Тут нам на помощь приходит концепция Observability. Она помогает отслеживать «состояние здоровья» сервисов и архитектуры.

## «Выбор подхода к мониторингу».
Везде используем «Четыре золотых сигнала», если это не проитворечит здравому смыслу в конкретной ситуации
- Задержка — это время, которое уходит на доставку запроса по сети от отправителя к получателю.
- Трафик — это показатель активности пользователей в вашем приложении. Его можно измерить с помощью любого высокоуровневого системного показателя. В веб-приложениях трафик обычно считают как количество HTTP-запросов в секунду.
- Ошибки — это частота неудачных запросов. Сюда относятся как явные ошибки (например, ошибки с кодом 500), так и неявные — например, статус запроса 200, но контент доставили неправильно.
- Насыщенность — этот параметр показывает, насколько «заполнена» ваша система. Насыщенность напрямую связана с показателем использования системы, но иногда её сложно измерить. Сбои могут возникнуть даже тогда, когда система не загружена на сто процентов. Поэтому важно определить целевой уровень использования.

таким образом следим за состоянием "машин", поможет выявить страннное использование ресурсов, что поможет сделать дальнейшее иследование какая утилита потребляет ресурсы
- CPU %

### internal shop
- Number of requests (RPS) for internet shop API -  - добавляем метки status. Метрика на каждую ручку. Помогает следить за текущей стиуацией
  
### shop/crm/mes api
- Number of requests (RPS) per user - помощь в выявлении ddos и странного поведения юзеров
- Response time (latency) - добавляем метки квантилей p50/p95/p99. Метрика на каждую ручку. Помогает следить за текущей стиуацией
- Number of HTTP <status> - добавляем метки status. Метрика на каждую ручку. Помогает следить за текущей стиуацией
- Number of simultanious sessions - контроль за пиковой нагрузкой
- Kb tranferred (received) - контроль за пиковой нагрузкой
- Kb provided (sent) - помогает выявить странности при релизах, например, резкое изменения объёма данных

### RabbitMQ
- Number of dead-letter-exchange letters in RabbitMQ - нам нужно следить что проихсодит в очереди, особенно при релизах
- Number of message in flight in RabbitMQ - нам нужно следить что проихсодит в очереди, особенно при релизах


### 3d files storage
- Size of S3 storage - можем наблюдать за изменением состояния, прогнозировать траты, и не скорость приближения к лимитам потребелиня

### mes/shop db
- Memory Utilisation for  db instance - можем наблюдать за изменением состояния, прогнозировать траты, и не скорость приближения к лимитам потребелиня 
- Number of connections for  db instance - можем наблюдать за изменением состояния, прогнозировать траты, и не скорость приближения к лимитам потребелиня
- Size of  db instance - можем наблюдать за изменением состояния, прогнозировать траты, и не скорость приближения к лимитам потребелиня
